Stack technologiczny

🐘
Backend
PHP 8.x
Czysty PHP bez frameworka. Pełna kontrola, zero narzutu. Każdy moduł to osobny katalog z plikami .php.
🗃️
Baza danych
SQLite 3
Jeden plik .db per organizacja. ACID, transakcje, pełna SQL. Backup przez VACUUM INTO — migawka bez blokady.
🎨
Frontend
Bootstrap 5.3
Bootstrap + vanilla JS. Bez React/Vue — strony renderowane server-side, szybkie, dostępne, indeksowalne.
📱
PWA
Service Worker
Cache-first dla statycznych zasobów, network-first dla PHP. Skróty aplikacji: Wiadomości i Zadania. Działa jak apka.
🔄
Multi-tenant
tenants/ per-org
Każda organizacja ma własny plik config w tenants/. Osobna baza danych, osobny katalog plików, izolowane dane.
📨
Powiadomienia
SMTP → e-mail
Kolejka mailowa w bazie, agent mail_queue wysyła co 5 min. Polling co 20s w przeglądarce dla wiadomości live.
Metody uwierzytelnienia — 4 sposoby logowania
🟦
Microsoft SSO
OAuth 2.0 z PKCE. Logowanie kontem Office 365 bez osobnego hasła do SZO.
PKCE + client_secret
🔑
Login + hasło
Klasyczna para login/hasło przechowywana w bazie jako hash. CSRF ochrona na każdym formularzu.
bcrypt hash
📟
Kod dostępu (IKA)
Indywidualny Kod Autoryzacyjny — jednorazowy link lub kod wydany przez admina. Działa bez hasła.
token jednorazowy
🆔
Weryfikacja PESEL
Opcjonalna warstwa weryfikacji tożsamości dla wrażliwych modułów — wymagana tylko tam, gdzie to konieczne.
per-module gate
🗂️
Role i zakresy
admin · editor · viewer · crm_user. Każda rola ma zakres widoku (portal_scope) i zestaw dozwolonych akcji.
can_edit() can_read()

Bezpieczeństwo

Ochrona danych
  • CSRF token na każdym formularzu POST
  • Hasła jako bcrypt hash, nigdy plaintext
  • Parametryzowane zapytania SQL (brak SQL injection)
  • Sesje izolowane per organizacja (tenant_slug)
  • Dane na własnym serwerze Fundacji
Kontrola dostępu
  • Kaskadowy model ról i uprawnień
  • IKA jako 2FA dla wrażliwych modułów
  • OAuth state w bazie — odporność na atak CSRF OAuth
  • Scope restrictions — viewer widzi tylko swój panel
  • Upload izolowany per organizacja
Backup i ciągłość
  • Automatyczny backup SQLite każdej nocy (2–4 AM)
  • VACUUM INTO — migawka bez blokowania bazy
  • Kompresja tar.gz, rotacja 30 dni
  • Lock-file mechanism — agenci nie nakładają się
Dostępność WCAG 2.1
  • ARIA labels na interaktywnych elementach
  • Nawigacja klawiaturą (focus-visible)
  • Skip link "Przejdź do treści"
  • prefers-reduced-motion — bez animacji na życzenie
  • Hierarchia nagłówków h1→h2→h3
PWA — działa jak aplikacja już teraz
Dodaj do ekranu telefonu z przeglądarki — działa bez App Store
Tryb standalone — bez paska adresu, jak natywna apka
Skróty z ekranu głównego: Wiadomości i Zadania
Ikony 192px i 512px, kolor motywu z brandingu organizacji
Service Worker — strategia cache
Cache-first dla CSS, JS, fontów — ładuje się natychmiastowo
Network-first dla stron PHP — zawsze świeże dane
Precaching powłoki przy instalacji Service Workera
Natywna aplikacja mobilna w przygotowaniu — PWA jako pomost

Backup danych — automatyczny, codzienny
Każdej nocy między 2 a 4 rano CRON uruchamia agenta backupu. Tworzy migawkę bazy przez VACUUM INTO (nie blokuje bazy w trakcie), pakuje do archiwum i rotuje — przechowywanych jest 30 ostatnich kopii. Dane nigdy nie opuszczają serwera Fundacji.
SQLite VACUUM INTO → tar.gz → rotacja 30 dni
